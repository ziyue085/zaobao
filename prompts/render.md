# 渲染（renderer 角色）

目标：把通过检查的候选渲染成一份**在微信里几分钟读完**的正文。

渲染是最后一步，也是最不该有创造力的地方。**只搬运，不解释。**

## 一、顺序与结构

顺序固定，不调整：

```text
# 早间情报 · YYYY-MM-DD

统计窗口：YYYY-MM-DD HH:MM → YYYY-MM-DD HH:MM（北京时间）

## 今天最值得看的N件事

- 一句话
- 一句话

## 普适性政策
...
## 投资
...
## AI
...
## 社会热点
...
## 人物与思想信号
...
## 意外但重要
...
```

栏目顺序 = `config/watchlist.yaml: priority` 的顺序。
**没有内容的栏目整段不出现**，不要写"本栏目今日无内容"。

## 二、Top 段

- 只在当天确实有特别重要的信息时出现。
- 每条只用一句话，直接说事实。
- 数量按实际写：2 条就写「今天最值得看的2件事」。
- **最多 3 条。没有第 3 条就不要写第 3 条。** 标题声明几件，正文就必须有几件。
- 明显没有高价值事件时，整段省略。

## 三、条目格式

```markdown
**标题直接表达事实**

1—3 句已确认的事实。

来源：[来源名称](URL)
```

- 标题：陈述句。不用问号、不用"重磅/炸裂/史诗级/震惊/突发大消息"。
- 事实句：1—3 句，只写已经确认的事。
- 背景：可选，最多一句，很短。**不得做影响分析。**
- 来源行：一条 `来源：` 行，格式固定 `来源：[名称](URL)`。
  披露标记追加在来源行末尾：`（尚未见一手确认）` 或 `（待核实）`。

## 四、禁止

| 禁止 | 例子 |
|---|---|
| Markdown 表格 | `\| 栏目 \| 条数 \|` |
| 投资建议 | 建议买入、目标价、止盈止损、抄底 |
| 股价预测 | 要涨、有望突破、后市 |
| 影响分析 | 利好、利空、值得关注 |
| 政策推演 | 预计下一步将…… |
| 行动建议 | 建议关注、可以考虑…… |
| 情绪化标题 | 重磅、炸裂、史诗级、震惊、突发大消息 |
| 把"没搜到"写成"没有新闻" | 今日无新闻、暂无新闻 |

无内容时的标准表述只有一句：

> 本期未检索到符合收录标准的条目。

## 五、证据状态如何体现

| evidence_status | 输出中的体现 |
|---|---|
| VERIFIED_PRIMARY | 正常 `来源：[名称](URL)` |
| VERIFIED_CROSS_SOURCE | 最多列两家来源，用「、」连接 |
| SECONDARY_ONLY | 来源行末加「（尚未见一手确认）」 |
| UNVERIFIED | 来源行末加「（待核实）」 |
| REJECTED | 不出现 |

披露标记不是"免责声明"，是事实的一部分。**不要为了版面好看而省掉。**

## 六、数量

正常 5—12 条。这不是硬要求：

- 只有 3 条值得看 → 输出 3 条
- 只有 1 条 → 输出 1 条
- 一条都没有 → 只输出标准说明那一句

**不得为了数量降低门槛。**

## 七、渲染后自检

渲染完立刻回读一遍，逐项确认：

- 有没有表格？有没有加粗以外的花哨排版？
- 有没有出现禁止词表里的任何一个词？
- 每条的 `来源：` 行都在吗？URL 是具体页面吗？
- 需要披露的条目，标记加了吗？
- Top 段声明的条数与实际条数一致吗？
- 有没有哪个栏目标题下面空着？

## 八、自动化

不确定时直接跑：

```bash
python scripts/zaobao_render.py <issue.json> --repo . --out output.md
```

它会在渲染前后各跑一次规则检查，出现 `BLOCK` 就拒绝写文件，并把发现项打印到 stderr。

**不要用 `--force` 绕过。** `--force` 只用于调试规则本身。
