# 核验（verifier 角色）

目标：为每条候选判定一个 `evidence_status`，并确认时间、去重、来源三件事都站得住。

核心态度：**宁可判低，不可判高。** 判高会让用户在微信里读到一条不实信息；判低最多是少发一条。

## 一、来源分层

### 第一优先级（primary，一手）

政府官网、中国人民银行、美联储、监管机构、交易所、公司公告、企业官网、官方博客、官方新闻稿、官方 GitHub、正式论文、作者原文、官方产品文档。

判一手的标准：**发布者就是这件事的主体本身**。

- 公司自己发的公告 → 一手
- 记者写的关于这家公司的报道 → 不是一手，哪怕记者是官方媒体的
- 论文作者自己放出的预印本 → 一手
- 别人转述这篇论文 → 不是一手

### 第二优先级（trusted_secondary，高质量新闻媒体）

只用于：发现线索、交叉核验、补充背景。

同一集团旗下的多个平台，**算一家**。不要用"同一篇通稿被十家媒体转载"去凑"多源印证"。

### 第三优先级（discovery_only，社交平台）

只用于发现线索。

**唯一例外**：发帖账号本身就是当事人、官方账号、公司负责人、项目负责人、论文作者。这时它升级为一手，但必须在来源备注里写清"发布账号即当事人本人"，并且系统会保留一条 WARN 提示复查。

## 二、判定流程

按顺序问，第一个"是"就停：

```text
1. 只有社交平台，且发帖者不是当事人/官方？      → REJECTED（不输出）
2. 有一手来源吗？                              → VERIFIED_PRIMARY
3. 有两家以上独立可信来源互证吗？               → VERIFIED_CROSS_SOURCE
4. 只有一家可信二手报道，但事情确实重要吗？      → SECONDARY_ONLY（必须披露）
5. 来源不足，但国外且极重要吗？                 → UNVERIFIED（必须披露，且只能进「意外但重要」）
6. 以上都不是                                  → REJECTED
```

## 三、披露标记（必填，不可省）

| 状态 | 必须标注 |
|---|---|
| SECONDARY_ONLY | 尚未见一手确认 |
| UNVERIFIED | 待核实 |

标注直接写进最终输出的来源行，例如：

```
来源：[TechCrunch](https://techcrunch.com/.../...)（尚未见一手确认）
```

不允许"用词暗示"代替标注。也不允许把标注写得很小、很绕。

## 四、时间核验

对每条候选确认三件事：

1. **原始事件时间**（不是报道时间、不是你知道的时间）。
2. 事件是否落在 24 小时窗口内。
3. 如果事件在窗外，是否出现了**实质新进展**？

实质新进展只认这些：官方确认、新公告、正式文件、新数据、新的处罚或判决、调查结果、新产品正式上线、传闻被正式证实或证伪。

**不认**：转载、重新讨论、媒体二次包装、热度回升、KOL 转发、"上热搜"。

只要出现实质新进展，状态就是 `UPDATED`，而不是 `NEW`。规范明确要求这个区分 —— 别用 `NEW` 混过去。

## 五、去重核验

1. 用 entity + action + object 生成 fingerprint（见 `references/dedup.md`）。
2. 对照 `data/history.jsonl` 最近 7 天以上记录。
3. 本期内部再查一遍。

命中历史且**没有**新进展 → `DUPLICATE`，不输出。
命中历史但**有**实质新进展 → `UPDATED`，可以输出，并在历史里记录 superseded。

## 六、URL 核验

- 必须能打开，且指向具体页面，不是首页、不是搜索页。
- 不能是搜索引擎结果页、聚合页、内容农场。
- `primary_url` 必须能在该候选的 `sources` 列表里找到。

## 七、最容易出错的三种情况

| 情况 | 正确做法 |
|---|---|
| 一条新闻被多家媒体转载，看起来"到处都是" | 看作一条，不是多条；转载不是印证 |
| 昨天的新闻今天有了新的媒体报道 | 判 OLD，不是 NEW；除非有实质新进展 |
| 论文/预印本刚出，还没有媒体跟进 | 论文原文就是一手来源，可以直接用 |

## 八、核验完必须能回答

- 这条的一手来源是什么？如果答不上来，说明它不是 VERIFIED_PRIMARY。
- 这条的确切发生时间是什么？如果答不上来，删掉。
- 这条在过去 7 天发过吗？不确定就查历史文件，不要凭记忆。
